# 登录验证的提交上下文与注册回滚

## 本批修复

- P1 `AUTH-SUBMIT-CONTEXT-01`：六位验证及密码重置只在点击时校验。550ms等待期间验证资料过期、被删除／替换、重新获取或撤销verified后，旧提交仍可能改写资料或继续导航。
- P1 `AUTH-REGISTER-PARTIAL-01`：注册逐键写个人资料、会话和空集合，中途容量失败会留下部分状态；验证码页还会先写verified再尝试注册。
- P2 `AUTH-CONTENT-KEY-01`：注册创建未被工坊使用的creations键，没有按实际仓库初始化works。

仅修改 prototype-auth-flow.js，保持原生JS和本地演示：

1. 验证及重置在实际执行前重新读取同一挑战，核对快照与有效期；变化时保留字段和当前资料，提示明确重新提交。
2. 注册复用已有 Preferences.transaction，一次安排个人资料、会话与缺失空集合；全部本地写入成功才清除挑战及注册草稿并导航。
3. 验证页完成注册前不再先改写verified，失败保留原资格和输入。
4. 初始化实际使用的records／moments／anniversaries／capsules／works／books。只补缺失项，不删除或重置已有数据；不再新建creations。

事务复用现有回滚工具。本批验证一次可恢复的容量故障后逐键原文完全相同，并能再次提交成功；不宣称本地存储具有数据库原子性或提供真实账号认证。
