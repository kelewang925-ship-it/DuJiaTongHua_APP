# 宠物页面真实姓名与可访问名称

P2-A11Y-PET-ART-NAME从p20扩展核对至全部25页。旧实现中，p01～p11只替换aria-label里的宠物名，漏掉人物名及浏览器标题；p12～p25只更新文本和screen名称，插画名称仍保留“糯米”等原稿姓名。25页普通昵称基线中5页通过、20页失败，不把所有页面都说成原先有同一缺陷。

## 修复范围

- 两个既有 `names(pet)` 统一调用轻量展示辅助层。25页custom/pages增加一个脚本引用，HTML正文、CSS、插画、模型、存储、原路由和照顾操作保持。
- 从首次渲染时的原UI模板读取文本、`aria-label`、`alt`、`title`属性和文档标题，用同一次正则回调插入真实宠物／本人／伙伴名字。昵称含“小满”“阿舟”“糯米”时不会再次解释成占位符，`$&`及引号／尖括号按原文插入，使用DOM文本和属性赋值。
- 再次调用沿原模板更新，不拿已经插入的昵称继续替换。控制器更换了原节点或字符串后，该内容不再由旧模板覆盖；新添加的用户内容也不作原稿姓名替换。输入框value和业务数据不改写。
- 实际“修改宠物名字”保存成功后，原paint之外补一次名称刷新，插画朗读名和浏览器标题立即更新；失败不刷新成新名，重载和其他标签页变化仍沿既有生命周期。
- 领养前宠物为空的p02／p04保持原空状态，不把未填写的昵称伪装成已领养宠物。
