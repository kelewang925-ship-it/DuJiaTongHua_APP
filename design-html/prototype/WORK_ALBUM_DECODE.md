# 工坊相册导出的异步解码边界

## 实际问题

- P1 `WORK-ALBUM-LATE-WRITE-01`：两个页面从同一完成作品点击保存。第一份导出完成后，用户在真正的照片编辑器修改并保存心情；第二份图片解码稍后完成，覆盖同ID照片并丢失心情。
- P2 `WORK-ALBUM-DECODE-ERROR-01`：原生Image.decode失败后，Toast直接显示英文浏览器异常，缺少可理解的下一步。

10项旧版本基线8通过、2失败。并发失败发生在实际第二次导出和实际照片编辑保存之后，不是替换业务函数的夹具。

## 修复

只修改 prototype-workshop-store.js：

- 在原有来源可见性、作品快照检查后，再读取稳定导出ID；如果另一份导出已完成，复用其当前内容，不迟到覆盖。
- 两处原生图片解码共用一个局部函数；失败提示“图片暂时无法读取，请重试保存”。
- 不改变原作品、canvas构图、照片编辑器或既有入口；生成结果仍通过真实Image.decode和canvas生成。

这是提交时重新读取的本地一致性保护，不是跨标签原子锁。没有引入真实接口或复杂状态架构。
