# 提交等待期间取消表单

## 问题与修复

P1 `FORM-PENDING-CANCEL-01`：宠物心情、回忆册改名在550ms保存等待期间点击取消／浏览器返回，会出现放弃确认，但等待结束仍写入。旧版4项实际复现均失败，用户尚未选择放弃／继续时已经写入，随后放弃也不能撤回。

修复复用 `UI.busy` 与 `UI.protectSheet`，每个表单用 WeakMap 关联本次提交：

- 等待阶段尝试关闭立即取消本次提交。未修改直接关闭；已修改仍选择继续编辑／放弃。
- 继续编辑保留字段，等待任务返回后恢复保存按钮；需要重新保存才写入。
- 放弃关闭后不写入，刷新也保持原记录。
- 业务回调已开始时，关闭会提示“正在完成保存，请稍候”，不显示可撤回的承诺。`protect.commit()` 标记成功，允许正常关闭；失败由 finally 清理，输入和重试入口保留。
- 按钮已离开文档时，不再启动等待中的业务回调。按钮原节点与 aria-busy 清理沿用原实现。

本批不接入远端请求，也不声称能够撤回已经执行的写入。

## 实际验证

| 检查 | 本批结果 | 范围 |
| --- | --- | --- |
| 修复前基线 | 4项失败 | 心情／改名×取消／浏览器返回；均观察到迟到写入 |
| 实际表单取消 | 96/96通过 | 16入口×取消、Escape、浏览器返回、遮罩、下滑、继续编辑再保存 |
| 共享操作边界 | 8/8通过 | 回调已开始的3种关闭×成功／失败；无修改取消；按钮移出文档 |
| 实际表单保存 | 47/47通过 | 正常保存、空值校验、存储空间异常保留与重试、防重复提交 |

16入口包括时刻回应、共同昵称、两个新标签入口、显示动效、手机绑定、两步验证、反馈、宠物心情、两个成长故事入口、成长回应、提醒时间、书页寄语、章节及改名。寄语／章节还验证父页最终保存；不把候选回填当成持久化。

取消检查仅暂存现有550ms等待计时器，在放弃／继续决定之前释放；执行真实业务函数与真实私有上下文 localStorage。96项全部检查决定前不写入；80项放弃检查关闭后和刷新后数据一致，16项继续编辑检查原输入及重试实际结果。8项边界是专用共享组件夹具，不能算8个真实页面。

旧隐藏弹层报告仅提供定位候选；每个测试重新检查实际标题、字段和数据结果。保存脚本增加显式 `--locator-candidates` 模式，报告声明候选来源与当前源码指纹，默认模式仍要求同一源码。
