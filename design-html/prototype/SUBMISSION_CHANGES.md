# 提交等待期间的内容变更与并发

> 当前文件选择捕获及47项相关检查点见[PENDING_IMAGE_READS](PENDING_IMAGE_READS.md)。本文件的234项矩阵保留bc21206源码指纹。

## 已复现的问题

4项旧版实际检查均失败：日记正文、日记回应在等待期间继续输入后仍保存旧内容；照片日期选择器未确认，底层保存已写入；工坊暂存与生成并发时，返回只能取消最后登记的任务，另一任务仍写入。

- P1 `PENDING-INPUT-STALE-01`：等待中的任务可能使用旧捕获值，随后清空输入或导航，丢失后续编辑。
- P1 `PENDING-PICKER-01`：选择器未确认时底层等待任务继续保存并离开。
- P1 `PENDING-DUPLICATE-01`：同一编辑范围多任务互相覆盖取消记录。

## 当前实现

复用已有guard根节点／弹层form、输入快照与单个WeakMap：

1. 同一保护范围已有任务时，第二个提交返回false，并提示“当前操作还在处理中，请稍候”。不同dialog表单保持独立范围。
2. `UI.busy`记录提交时的值；页面使用guard原有value函数，表单使用现有字段快照。550ms等待结束、业务回调开始前重新核对；值变化则停止，保留当前输入并提示“内容已更新，请重新提交”。重新保存时使用最新输入。
3. 打开modal／选择器会取消仍在等待的底层页面任务。选择器自身的确认／取消继续原有行为，父页需要重新提交。
4. 任务退出仍由finally恢复原按钮节点与aria-busy，清理所属提交记录；异常重试继续使用现有逻辑。

等待阶段继续编辑会保留最新输入，需再次点击提交后才执行新的保存回调。
