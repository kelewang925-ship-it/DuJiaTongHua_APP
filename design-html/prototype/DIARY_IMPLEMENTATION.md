## 数据合同

`prototype-records.js` 提供 all/find/put/remove/route，小集合直接读写 `dujia-prototype-records`，更新一项保留其他类型记录。日记结构：

```text
id, type=diary, title, body, mood, visibility=shared|private,
status=draft|published, author, createdAt, updatedAt,
image=dataURL|null, sampleImage, comments=[{id,author,text,createdAt}]
```

不存在集合时，日记预览可初始化三篇示例；明确的空数组绝不补回示例。注册初始化空集合，从首页首次记录开始。示例插画只属于明确示例项；用户新建无照片的记录用文字占位区遮去底图照片。原 `dujia-diary-draft` 单篇草稿键不再承担新流程的保存，不自动把旧不完整数据冒充新发布记录。

`dujia-diary-list-state` 保存标签与可见条件，`dujia-prototype-last-query` 保存当前查询（sessionStorage）；`dujia-prototype-search-history` 存最近6次查询（localStorage）。没有真实网络或上传。

失败评审值 `dujia-prototype-fail-next`：`diary-save`、`diary-image`、`diary-load`、`diary-comment`、`diary-delete`、`record-search`。容量失败由测试临时拒绝对应Storage写入模拟，恢复后重试。

## 修复记录

- P0：只写草稿/提示保存，列表和详情不消费数据 → 统一ID集合与完整CRUD。
- P1：所有列表卡片指向同一编辑器 → 按ID及发布/可见状态导航。
- P1：草稿和筛选只有提示 → 实际条件、数量、无结果与清除入口。
- P1：留言只清输入 → 同记录下持久留言、失败保留。
- P1：新发布内容被旧筛选隐藏 → 发布返回列表选择对应标签并清筛选。
- P1：共享busy恢复textContent丢失SVG → 保存和恢复原子节点；发送图标有回归检查。
- P1：无照片记录仍显示底图示例 → 空照片遮盖与实际上传图片展示。
- P1：首页与搜索仍是静态示例 → 本地日记更新首页并按查询/ID打开。
