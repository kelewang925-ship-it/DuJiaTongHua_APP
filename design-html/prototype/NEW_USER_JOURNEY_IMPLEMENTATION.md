# 首次注册、绑定与日记的连续流程

## 复现与修复

两条使用全新浏览器的流程没有写入业务fixture或清库：

1. 欢迎→注册→验证码→关系入口→输入邀请→确认关联。在这里找不到进入空首页的入口，成功页只允许写第一篇日记或完善资料。
2. 空首页→新建日记→保存→日记列表。标示“返回首页”的控件实际调用历史返回，重新进入已完成编辑器。

首次基线保留两条失败。修复导航后进一步核对关联成功页，发现昵称与关联日期仍是固定设计稿文案；身份基线保留一条失败和已修好的列表返回通过，独立记录，不覆盖最初证据。

实际修改：

- 关联成功页下方增加共享TextButton“先逛逛我们的首页”，替换当前成功页进入实际空/正常首页。两项原有任务保持原位置；新增入口放在原画板之外，保留画板比例，页面允许滚动。
- 成功页昵称、伙伴、日期读取刚保存的profile/relationship及acceptedAt，不再把固定日期当作实际建立日期。
- 日记列表顶部返回使用明确首页落点，详情顶部返回日记列表并保留列表session条件，不依赖已经完成的编辑器历史。编辑器返回仍使用未保存保护与原历史/fallback。
