# 共同资料的提交上下文检查

## 问题与修复

P1 `WORLD-WRITE-CONTEXT-01`：共同头像读取、昵称保存和解除关联请求使用页面加载时的资料。另一页更新资料、关闭共同空间、解除／替换关联或切换账号后，旧操作仍可能写入并覆盖新数据。关联状态弹窗也会展示旧状态。31项旧版本实测中7项通过、24项失败；基线报告完整保留，原执行终端输出未保留，不补写退出码。

本批仅修改 m06-p03 的既有控制器，复用 UI.read／canWrite／write、表单保护与原生图片读取工具：

- 进入管理和查看状态时重新读取资料。
- 选图打开前、昵称编辑打开前、解除确认打开前记录关联身份和会话标记；提交时核对当前状态。
- 头像与昵称只比较各自字段，避免覆盖其他页面对同一字段的修改；独立字段及解除请求则合并保留。
- 头像的检查从打开选图入口开始，覆盖选中图片之前及原生读取期间的变化。
- 昵称被拒绝后保留输入和未保存退出保护；重新进入编辑可确认最新资料。
- 已有解除请求不重复替换，解除仍允许在共同空间关闭时发起。
- 头像被其他页面清空时恢复原图标节点；没有新增布局或样式。

保持原型既有进入策略：已关联的直接演示页面不新增登录门槛。会话标记用于阻止操作期间账号变化造成的迟到提交；不是实际账号鉴权。
