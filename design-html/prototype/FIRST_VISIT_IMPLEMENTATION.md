# 首次访问与等待领养返回（阶段记录）

## 根因与修复

- 日记控制器只因记录键不存在，就写入三篇示例；打开新建编辑器也会触发。照片、时刻、纪念日控制器有相同的示例写入分支。
- 首页把“键尚不存在”视为保留正常稿的理由，因此新浏览器直达正常首页会展示示例记录。
- 等待领养页顶部返回默认到首次领养页；已存在pending邀请时该页又重定向回等待页。真实提交邀请后的浏览器历史还包含已经不能重新进入的领养表单。

删除四处自动示例写入；首页始终按实际记录选择正常/空状态，并从实际集合绘制最近记录。不删除、覆盖或迁移已有数据；旧版本已写入的示例不会被猜测为可自动清理的数据。正常态可通过实际创建内容和显式测试fixture展示。

等待页的顶部与“暂时返回”统一replace到首页目标，由首页控制器选择空/正常态。保留pending邀请，未取消、重建或确认领养。顶部返回不再进入已提交表单。

## 有名证据

`verify_first_visit.py` 在全新隔离存储运行，不预先填入空数组：12个入口检查实际落点、没有自动内容和无脚本错误；另检查第一篇日记保存/列表/首页一致、已有三类集合不变、两种直达历史返回及实际选择/提交领养后的顶部返回。共17项。

实施前 `first-visit-results.json` 16项中10项失败、6项原本通过；独立的 `first-pending-extra-results.json` 实际提交领养返回也失败。修复后17项通过，不将额外用例伪称为原16项的一部分。

原日记、照片、时刻、纪念日和宠物主流程及一级导航进行针对性回归。最终条数与文件哈希见 `evidence/current/first-visit-checkpoint.json`。
