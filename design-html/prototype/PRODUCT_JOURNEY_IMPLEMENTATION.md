# 八模块连续使用与真实新建内容联动

## 目标与范围

在全新浏览器上下文中从注册开始，用页面控件创建内容，连续经过账号、关系、首页记录、时刻、宠物、工坊、个人设置和回忆册八个模块。保持可编辑 HTML、本地模拟数据和既有页面设计；本阶段属于现有逻辑修复与综合流程验证。

执行脚本为 `verify_product_journey.py`。除了首次打开欢迎页，主页面不使用脚本跳转到业务页面，不预置业务集合、不在途中清库。另一位参与者缺席时，通过同一上下文的独立标签页打开已有 review 演示入口并点击“另一半同意领养”；这是明确的本地第二参与者模拟。日记保存、工坊生成、再次登录各注入一次已有失败开关，失败后通过页面重试。

## 连续流程

| 阶段 | 实际操作与检查 |
| --- | --- |
| 首次使用 | 注册星星、验证码、接受本地邀请、绑定、空首页；首篇日记保存失败保留输入，继续保存、列表、详情、编辑、刷新、取消删除、确认删除后回到空首页 |
| 共同记录与时刻 | 再次新建共同日记；首页当天关联天数为0；新建时刻并关联该日记的实际稳定ID |
| 宠物 | 申请领养星团、另一位参与者确认、主页面接收变化；互动、喂食、添水与周奖励；手动保存成长故事 |
| 工坊 | 从刚创建的共同日记生成漫画；失败后重试完成，保存实际照片到相册；结果返回创作列表，再回工坊 |
| 回忆册 | 使用刚创建的日记、照片、时刻、作品、成长故事五类真实素材，逐页选择模板、编辑、保存、编排、发布 |
| 阅读与管理 | 阅读首个书页、书签、工具、补页留言、回到原工具入口、改名；触发真实JSON下载并检查册ID及5个书页 |
| 退出与再次登录 | 返回首页看到实际册名；个人设置退出，内容集合、宠物及关系保留；模拟登录失败保留输入，再次登录后恢复这些内容和书签，不持久化密码 |
| 删除联动 | 从首页继续阅读并进入管理；取消删除保持册，确认删除回到空书架；原日记、照片、时刻、工坊作品及宠物不随册删除 |

步骤快照、实际导航轨迹和错误记录见 `evidence/current/product-journey-results.json`。不同类型素材可能同名，选择器同时检查标题与种类，避免把日记、照片和作品混为同一来源。

## 三个实际问题与修复

| 问题 | 原因与修复 | 复现及回归证据 |
| --- | --- | --- |
| 生成完成后返回绕回结果页 | 结果页普通历史返回进入生成页，已完成任务再次跳转结果。结果顶部显式替换到创作列表，列表顶部替换到工坊；浏览器back与BFCache遇到已完成任务时按会话返回上下文进入列表/工坊。只跳过ready任务，草稿及取消流程沿用原保护 | baseline/product-journey-result-back-loop.json、baseline/workshop-task-return-results.json；current/workshop-task-return-results.json，正常/失败重试×按钮/浏览器共4项 |
| 新日记不进入回忆册当月素材 | 日记保存有createdAt，没有date；素材月份过滤只读取date。素材读取时优先使用显式date，否则从有效数字createdAt取本地日历日期；不修改原记录，不改变私密/草稿过滤 | baseline/product-journey-created-date-source-missing.json；current/book-created-date-results.json，5项 |
| 新用户显示设计稿428天 | 没有相识日期时未覆盖静态计数。使用已有日历工具：有效相识日期优先，已绑定且仅有acceptedAt时显示“我们已关联”及关联天数；未知日期显示待补充，未绑定显示等待；未来日期钳制0 | baseline/home-counter-results.json中3个实际失败；current/home-counter-results.json，6项；完整连续流程同时检查新绑定0天 |

首页专项使用有共同记录的正常首页检查计数；空首页m03-p01本来没有该计数，不将无节点误认为产品问题。日期专项声明Asia/Shanghai、2026-10-06；createdAt测试时间在本地跨日边界附近，证明按本地日历取值。记录和关系存储在这些只读检查中保持不变。
