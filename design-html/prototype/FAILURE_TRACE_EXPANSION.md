# 第二批失败操作追踪

本批六组50个案例最终通过：纪念日7、胶囊5、日记12、时刻6、工坊8、宠物成长12。累计11组80个案例，实际观察52种失败操作；61个字面量候选中36个已观察，25个未追踪。其余16个实际操作通过动态入口传参。不得把已观察等同于该操作所有条件终验。

## 修正的验证缺口

- 日记列表旧测试没有创建记录，却在失败重试后期待卡片。原型实际展示空态正确。先验证空列表失败后能重试到空态，再用真实表单创建日记，验证有数据时失败重试与刷新均显示保存的内容。第一次11/12失败报告及旧脚本已保留；最终12/12。
- 胶囊删除旧断言可能读到上一步开关失败的Toast，在异步删除运行前即导航离开。第一次追踪只观察到collect/load/toggle，不能据此证明delete失败。增加等待失败标记消费后，最终实际观察到capsule-delete，存储中胶囊仍保留。不能以旧“通过”结果扩大覆盖。

## 保存证据的方法

run_isolated_failure_trace.py调用既有追踪器，单独保存failure-traced-报告与failure-traces/screenshots，再恢复原报告和截图。日记宽度截图的额外前缀也已纳入保存规则。原工坊／时间回归报告、页面控件报告及151份产品源码均保持原字节。本批没有改产品交互。

failure-operation-matrix.json和FAILURE_OPERATION_MATRIX.md明确列出25个未追踪字面量入口；静态脚本引用仅作发现线索。failure-trace-executions.json包含真实进程和失败重试，历史矩阵与旧执行说明另存history/pre-isolated-failure-traces-53fb10f。所有最终报告、脚本、事件和HTTP源码由build_failure_operation_matrix校验。
