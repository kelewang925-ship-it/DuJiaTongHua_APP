# Toast顶层可见性与关键操作避让

## 复现与修复

G4实际复现了两类问题：

旧检查中的DOM有文字或`to_be_visible()`不等于提示在原生dialog顶层真实可见。本批增加了所属顶层子树、操作区域几何、关闭交接及实际截图检查。

- P1反馈不可见：书名dialog打开时，同源另一窗口更新回忆册触发Toast；Toast仍在body，原生dialog顶层把它盖住，用户看不到数据已变化的提示。
- P2视觉覆盖：日记编辑器320×844、390×420的长success／info覆盖保存按钮区域。原Toast已设pointer-events:none，因此不是“点击被拦截”，但按钮视觉被遮挡。

继续使用`PrototypeUI.toast(message, kind)`与原有色彩、字体、三类语义和2600ms计时。Toast显示时挂到当前dialog子树或body；dialog内首选安全区顶部。局部定位读取可见提交、busy、共享Primary、导航及焦点按钮边界，选择最近的可用垂直间隔。弹层关闭时将同一Toast移回body并重新定位，剩余计时保持，不重启，也不移走字段或焦点。

22项包含两宽度／两高度的12个布局合同、两动效模式下4个真实peer更新和取消交接、2个实际本地书名保存、三类真实壁钟自动消失以及新提示替换旧计时。确认本地输入／数据保持，无新增pageerror；少量截图已查看，仍不填写人工验收人。

正式前后证据为`evidence/baseline/toast-feedback/`与`evidence/current/toast-feedback/`。另一个`baseline/toast-layout/`含诊断和临时DOM候选截图，不当作正式修复通过结果。

## 影响范围与保留证据

产品仅改变私有Toast定位、调用挂载、dialog关闭时的提示交接，以及一条Toast专用CSS。`audit_toast_scope.cjs`通过AST核对：扣除这些明确节点，其他UI语义完全相同；扣除该规则，其他CSS原文相同。数据写入、未保存比较、提交、返回、历史与业务回调保持。

此前270提交、190列表与114截图保留原源码清单和实际执行，不把哈希改成新版本。此次22＋20项及差异范围证明组成最新保留依据；它们不是上述旧套件全量重跑。114初始截图继续作为原状态对照包，新增Toast动态画面见本批截图。当前校验入口为`verify_toast_feedback_checkpoint.py`，旧版本绑定的校验器在新源上拒绝匹配是正确边界。

G4这组明确缺口已修复并自检；G3隐藏动作对应与G5人工原稿对照继续，完整目标未结束。
