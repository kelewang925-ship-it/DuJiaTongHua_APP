# 个人与关系资料的损坏恢复

范围是 `dujia-profile` 与 `dujia-prototype-relationship`。仍为本地演示，不是账号认证服务。会话、邀请码、其他集合及114页最终验收继续开放。

## 复现与修复

基线5项中，4项失败、正常资料1项通过：null个人资料使成功页读取昵称报错，null关系使设置入口报错；坏JSON和数组根结构缺少恢复提示。

共享UI读取这两种资料时验证对象结构、已知文本字段、曾用昵称数组、头像、时间及共同资料/解除请求的结构。返回可读字段供页面显示，但不改写原始字符串。提供“资料需要恢复”Modal和“恢复资料”按钮，原文可实际下载；确认后先保存完整副本，再写入可读资料。未知字段保留，不冒充已经验证全部业务日期、颜色、身份或权限。

恢复前，普通UI.write与标签事务暂停保存，避免覆盖资料或使用错误身份创建内容；原始副本保存仍可执行。正常资料不进入此限制，也不被自动重写。明确确认的注销演示账号仍可清除本地数据。

备份前后检查快照，发现其他页面的新内容停止替换；两种容量失败保留主资料，主写入失败仍保留副本。成功后的刷新经过共享未保存确认，继续编辑保留昵称，随后可保存。多个问题依次恢复：个人资料、关系资料、记录，避免恢复弹层相互替换。原始资料副本使用account-recovery前缀，也可从数据与存储的既有副本历史入口再次下载。

这是本地快照保护，不是跨进程数据库事务。没有真实API、登录、推送或权限服务。

## 控件与出口

| 控件/状态 | 实际行为 |
| --- | --- |
| 恢复资料 | 重新检查当前资料，优先个人资料，再关系资料；没有问题时移除入口 |
| 稍后处理 | 关闭弹层，保留原文和页面输入，普通保存仍暂停 |
| 导出原始资料 | 下载当前原始字符串，随后重新显示恢复选择，不写主资料 |
| 恢复可读资料 | 进入第二次确认，不立即替换资料 |
| 重新检查 | 再次读取；问题已消失时安全刷新当前页，仍遵循未保存确认 |
| 第二次确认：取消 | 返回恢复选择，主资料及副本不变 |
| 第二次确认：确认恢复 | 留副本、快照检查、写可读字段，成功后安全刷新；失败不调用成功导航 |
| 未保存确认：继续编辑 | 保持原字段值，可在恢复后的集合上再次保存 |
| 原始副本历史 | 只下载，不导入或覆盖；普通导出/共同备份不包含原文 |

表中声明行为与20项实际执行范围分别记录；不把代码存在或未执行的全部关闭方式当成已终验。

## 证据

20项资料专项检查：4种损坏、正常数据、共同字段保留、两种容量失败、确认前和备份期间并发更新、未保存昵称、事务保护、无效新资料拒绝、三类数据连续恢复、历史下载及5种手机宽度。下载检查实际文件，保护检查实际存储与表单值。

图像复查发现固定“恢复资料”按钮在320/360px遮挡底层操作。补充底层控件点击检查的基线为2失败/3通过；入口改为画板外可滚动区域，原画板尺寸不变，五宽度下原有操作、首页出口和恢复入口均可点击并满足安全区。保留浮动布局的此前全页观察，最终源码另行刷新，不能沿用该中间版本的源文件指纹。

另有账号8项、无预置内容连续流程2项、设置5项、记录恢复21项、副本15项、宠物3项、回忆册4项、工坊3项正常/异常回归。账号82个初始控件和14项弹层复查、114页228次观察及当前HTTP源码一致性以account-recovery-checkpoint.json为准；各项检查不累加历史重复运行。

多问题测试首轮在页面刷新时执行存储断言，第二轮把Modal关闭的同URL历史回退误当成刷新完成；失败观察原文分别保留。脚本改为等待实际load事件后再读取，三类数据按实际入口连续恢复通过，没有据此修改产品等待时间。其他新增检查不声称有旧失败基线。

资料恢复不会清空记录/草稿；普通导出和共同备份不包含原始资料副本。其他集合的坏结构、会话/邀请码恢复、全状态长文字/键盘/视觉和完整控件终验继续实施，最终验收0页。
