# 纪念日、提醒与胶囊的连续使用

## 范围与流程

从空浏览器注册、验证及关联关系开始，完成首篇日记的失败保存、编辑、刷新、取消/确认删除后，从产品入口继续操作。主页面只在最初打开欢迎页，之后没有脚本跳转到指定业务页面、清库或预置业务集合；本地失败开关只影响下一次实际操作。新流程采用Asia/Shanghai、本机当天及次日，没有改计算机时间。

| 阶段 | 实际操作及结果 |
| --- | --- |
| 真实关联 | 空时刻册创建重要时刻；添加当天纪念日并关联该时刻ID；保存失败保留输入和集合，未保存返回继续编辑后重试成功 |
| 当天日记 | 纪念日写日记带实际anniversaryId；回首页从真实纪念日进入当天页，能看到并重新打开该日记 |
| 纪念日编辑 | 改名并改为明天、提前3天提醒；稳定ID、关联时刻和日记保留；保存回倒计时，顶部返回列表 |
| 胶囊草稿 | 真实上传非法文件有错误反馈；合法测试PNG预览；暂存、从草稿tab继续，实际照片与文字保持 |
| 封存与开启 | 封存失败保持草稿；重试保持同一ID。未开启时不渲染信件/照片；提醒开关失败保持原值，重试生效；从共同提醒进入胶囊，开启失败保留sealed，重试后显示真实信件及照片 |
| 收录与删除 | 收录失败不改变两个集合；成功生成稳定关联时刻，再收录不重复；取消删除保留，失败删除可重试，最终删除胶囊保留已收录时刻 |
| 提醒及纪念日删除 | 已删胶囊不再显示提醒；纪念日提醒消费实际ID并标记已读；取消/失败/确认删除纪念日；空提醒保留原日记、原时刻及胶囊收录时刻 |

连续结果、步骤存储快照和实际导航轨迹见 `evidence/current/time-product-journey-results.json`，截图位于time-product-journey。PNG仅为本地文件读取测试样本，不是新的设计素材。

## 已复现问题与修复

| 问题 | 原因及修正 | 实际证据 |
| --- | --- | --- |
| 当天页找不到关联日记 | 倒计时会列出关联共同记录，当天分支未使用该数据。两种详情复用同一published/shared过滤；当天在原画板后添加可滚动的“今天留下的共同记录”，按钮复用共享Button，携带实际ID | baseline/time-product-journey-results.json在当天页查找真实新日记失败；连续流程与15项宽度检查 |
| 保存后按钮/浏览器返回旧编辑器 | 普通push把完成编辑器留在历史；表单guard另有anchor和sentinel，仅location.replace仍留下anchor。新增guard.complete(url)，仅在写入成功后提交基线、退到anchor再替换为结果；当前只供纪念日保存、胶囊暂存/封存使用。纪念日详情/列表、胶囊详情/列表顶部有明确上级出口；编辑器仍走原dirty保护 | baseline/time-task-return-results.json的5条真实任务返回失败；第一版4通过/2浏览器失败保留time-task-return-first-fix.json；修复后6项返回/入口及原7项dirty/事务/已读失败检查 |
| 提醒页没有正常入口 | 原时刻册只有纪念日/胶囊/留言入口，提醒页只可目录直达。正常/空时刻册的原画板后新增共享“共同提醒”Button，进入提醒控制器，由实际内容决定正常/空态 | 第6条入口失败基线、正常连续提醒操作及空态入口专项 |
| 新提醒入口被底部导航遮住 | 360/390px时默认滚动仅保证进入视口，固定底部导航仍挡住中心点。入口设置按导航高度、安全区及16px计算的scroll-margin-bottom | baseline/time-entry-nav-overlap-results.json中4项实际中心命中失败；15项五宽度全部实际中心命中、聚焦、Enter打开并检查存储 |

“仅替换”第一版失败属于未彻底修复的真实历史缺陷。另一个连续脚本曾假定纪念日列表有一级底部Tab，实际该页需要顶部返回时刻册；此观察错误另存time-product-journey-nav-observer.json及截图，没有增加不存在的Tab。

人工检查320px长标题截图确认原画板不被新增区遮挡、文本换行、焦点轮廓完整。正常动效下当天页的第一张截图尚在220ms淡入途中；旧图保留time-today-before-motion-finish.png，当前stage等待画板实际动画finished后再截取，不把中间帧当作稳定视觉结果。

随后复查发现仅等待动画仍可能在关联区就绪前获取完整高度，旧图另存time-today-before-related-ready.png。当前当天快照明确等待真实日记按钮可见，再等字体/动画；最终截图已人工确认真实关联日记在原画板后呈现。390px空时刻册提醒截图显示焦点和入口在底部导航之上；这些仅证明指定状态，没有扩展为全114页视觉验收。

## 共享完成任务合同

- 保存校验、Loading及写入先执行；写入失败不调用complete，不更改原dirty基线，输入和当前页保留。
- 成功后complete把已保存输入作为基线；若当前有guard sentinel，等待现有pendingPop消费这一次返回，再替换anchor到目标页面，避免产生旧完成编辑器。
- 它不改变普通guard.commit、未保存返回、弹层关闭或其他模块的既有保存实现；这些边界用实际原有检查重新验证。其他多步骤任务仍须按各自入口逐项审计，不由这两种表单扩展为全产品历史通过。
- 浏览器返回证据属于HTML语义验证，没有Android物理返回实测。
