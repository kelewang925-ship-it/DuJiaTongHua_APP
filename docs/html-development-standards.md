# 《独家童话》HTML 页面开发与验收规范

> 适用范围：`codex/design-html-rebuild` 分支的 114 页 HTML 高保真还原、交互原型和验收记录。遵守根目录 `AGENTS.md`；本规范仅补充 HTML 阶段约束，不替代既有设计系统与页面清单。页面路径、基准视口、已有组件和黄金页面名单以仓库实际资料核实为准，不得猜测。

## 一、修改前检查

1. 阅读 `AGENTS.md`、目标页面关联的设计稿、原型、现有文档和页面验收记录。
2. 检查 Git 工作区和目标分支；搜索同名页面、公共 HTML 组件、CSS 变量、JS 工具、设计资源及既有规范。优先复用，不得并行创建第二套标准。
3. 核对页面编号、文件路径、资源引用、原型跳转及页面依赖；无法确定时登记“待核实”，不得自行推断。
4. 识别已验收黄金页面；未获明确授权不得覆盖、重构或修改其依赖而导致视觉变化。
5. 仅修改当前批准的页面或文档；跨页公共样式改动须列出受影响页面并取得确认。

## 二、HTML 与视觉实现

- 使用可读、语义合理的真实 HTML/CSS 结构，不以单张整页图片代替可编辑页面。设计插画、纹理和图标可以作为资源使用。
- 保持《独家童话》设计稿的绘本感、奶油纸感、柔粉与手绘贴纸风格；以原稿及现有设计 Token 为最终依据，不擅自替换色彩、字体、尺寸、文案或素材。
- 优先复用已有公共组件、CSS 自定义属性、样式和 JS 工具；不重复定义已有变量、不复制整套公共样式到单页。新增变量应说明理由和作用域。
- 文件命名、资源路径和页面编号遵循仓库既有约定；使用可追溯的相对路径或项目既定映射，避免硬编码个人本地绝对路径。
- 注意移动端安全区、内容滚动、文本溢出、层级、弹层遮挡、图片比例、交互触达和页面溢出；不以破坏结构的绝对定位作为普遍修复手段。
- 任何对共享 CSS/JS 的变更均需检查依赖页面，不得以局部截图通过代替回归验证。

## 三、交互与状态

- 每个可点击按钮、链接、标签和图标均有明确行为；无功能的控件不得伪装为可用。页面跳转严格遵循现有原型；未知目标登记待确认。
- 弹窗、Bottom Sheet 应实现打开、关闭、取消/确认（如设计需要）、遮罩和滚动处理；返回行为与现有原型一致。
- 表单具备输入、焦点、基本校验、禁用和提交反馈；避免无响应点击。Loading、Empty、Error、成功及异常状态按设计要求覆盖，不凭空新增不属于设计的界面。
- 无后端时允许 Mock 数据，必须在实现与记录中明确标注模拟行为；不得展示“真实提交成功”“已同步服务器”等虚假结果。
- 页面验收须测试关键路径和异常路径；静态页面截图不能证明交互完成。

## 四、视觉验证

1. 先查找仓库既有截图基准视口；如不存在，暂用 `390 × 844 CSS px` 作为**待确认临时基准**，设备像素比、浏览器、缩放、字体加载和截图方式须写入记录。未经确认不得将临时值视为最终项目标准。
2. 在相同视口、相同页面状态与数据条件下，保存原始设计稿引用和 HTML 截图；对照检查布局、背景/颜色、文字、字体、间距、资源、边框/阴影、滚动与安全区。
3. 记录可复现的明显差异，包含位置、现象、严重程度、截图路径和修复状态；不得仅凭文件存在、脚本运行或截图生成判定完成。
4. 自动化截图、静态检查和控制台检查只提供辅助证据；“视觉验收已通过”必须有人工对照确认及验收记录。
5. 无法运行页面或缺少原稿时标为“待核实/待验收”，不可伪造截图、测试结果或人工结论。

## 五、页面状态与验收记录

使用现有页面清单作为唯一事实来源；若没有统一记录格式，按以下字段补充到现有文档/表格，不要创建重复的 114 页清单。

| 字段 | 要求 |
| --- | --- |
| 页面编号 | 与原始设计稿/既有清单一致，唯一 |
| 页面名称 | 与原型一致 |
| 原始设计稿路径 | 仓库相对路径；未知写“待核实” |
| HTML 文件路径 | 仓库相对路径；不存在写“未创建” |
| 页面开发状态 | 未开始 / 进行中 / 待验收 / 已通过 / 需返工 |
| 交互完成状态 | 未开始 / 进行中 / 待验收 / 已通过 / 需返工 / 不适用 |
| 视觉验收状态 | 未开始 / 待验收 / 已通过 / 需返工 |
| 存在的问题 | 问题编号、严重程度、复现方式、待处理事项；没有写“无已知问题” |
| 最近验证记录 | 日期时间、执行人、视口与环境、截图/日志路径、结果、人工验收人（若有） |
| 黄金页面标记 | 是 / 否 / 待核实；已通过不自动等于黄金页面 |

状态判定：`未开始` 为尚未实施；`进行中` 为正在实现或修复；`待验收` 为实现自检后等待人工确认；`已通过` 为该维度证据齐全且经相应验收；`需返工` 为验收发现阻断问题。三个维度独立更新，不能因为 HTML 存在就全部设为已通过。

## 六、黄金页面及变更边界

- 已验收黄金页面默认只读；若需修改，先列明页面编号、变更原因、相关资源/公共样式影响、回滚方式和重新验收计划，获得确认后再实施。
- 不修改现有业务功能、不开展 Expo 页面迁移、不删除设计资源、不覆盖黄金页面、不对 114 页执行未经确认的批量重构。
- 批量脚本仅可在明确授权范围内运行；任何批量修改前先预览 diff、备份或保留可回滚提交，并抽样验证。
- 规范建设阶段仅修改必要文档；不借此修复页面、不改路由、不引入新依赖。

## 七、单页完成定义（DoD）

页面只有在以下条件全部满足后，才能宣称“整体完成”：路径和原稿可追溯；真实 HTML/CSS 实现；设计资源正确；必要的交互和状态已验证；统一视口下截图与原稿对照完成；问题关闭或明确接受；人工视觉验收留痕。未满足者应分别标注开发、交互、视觉状态，不得汇总为已完成。

## 八、规范建设交付与待确认项

每次规范建设提交报告：检查过的现有规范、新增/修改文件、开发约束、对现有页面的潜在影响、尚待确认问题。至少核实：实际 114 页主清单、黄金页面名单、截图基准与存放位置、现有组件与 Token 入口、原型路由来源、验收责任人。无法核实的信息保留“待核实”，不做推断。

本文件不宣称已对 114 页逐一检查，也不构成任何页面的人工验收。
