## 方案

采用“公开展示专用仓库”方案：在资料根目录初始化独立 Git 仓库，但通过忽略规则和显式暂存，只跟踪公开站点需要的文件。

远端仓库包含：

- `index.html`：由当前展示页生成的公网入口；
- `README.md`：说明仓库用途、线上地址和公开内容边界；
- `.nojekyll`：关闭不需要的 Jekyll 处理；
- `.gitignore`：默认忽略本地完整资料，防止后续误上传；
- `.github/workflows/pages.yml`：部署 GitHub Pages 的工作流；
- HTML 实际引用的 99 个图片、流程图或文档文件，保留原有相对目录结构。

本地未公开资料继续存在于同一资料根目录中，但保持未跟踪和被忽略状态。

## 公开范围与安全

上传前执行以下检查：

1. 根据 HTML 的 `src` 和本地文件型 `href` 引用生成公开文件清单。
2. 确认清单中的文件全部位于资料根目录内，禁止路径越界。
3. 检查待提交文本文件中是否存在令牌、密码、Supabase 密钥、邮箱、手机号或本机绝对路径。
4. 检查 Git 暂存区，确保只有批准的站点文件和资源。
5. 不提交本地完整资料、历史未通过设计稿或与展示页无关的生成资产。

## Git 与发布流程

1. 在资料根目录初始化 `main` 分支 Git 仓库。
2. 添加远端 `origin`。
3. 创建忽略规则、入口文件、README、`.nojekyll` 和 Pages 工作流。
4. 只暂存批准的公开文件清单。
5. 验证暂存文件数量、总体积、单文件大小和敏感信息检查结果。
6. 创建首次提交并推送 `main`。
7. 使用 GitHub Pages 工作流发布站点。
8. 等待部署完成并检查公网入口。

工作流只上传 Git 已跟踪的公开站点内容，不读取或发布被忽略的本地完整资料。

## 验证标准

- 远端仓库可以公开访问，且不包含完整本地资料。
- GitHub Pages 首页返回成功状态，并能显示项目 Logo、模块、流程图和设计稿。
- HTML 的全部公开资源引用均可访问，无缺图。
- 8 个模块入口能在当前页面打开对应设计稿筛选结果。
- 流程图支持按钮、键盘、拖动和滚轮缩放，范围保持 50%–500%。
- 桌面和移动宽度下页面没有明显横向溢出或不可操作区域。
- Git 工作区中的本地未公开资料被忽略，后续普通 `git add .` 不会误提交。

## 失败处理与回滚

- 如果推送因认证失败而停止，不修改远端状态，保留本地提交，待用户完成 GitHub 登录后重试。
- 如果 Pages 工作流失败，先查看工作流日志并修复发布配置，不改用上传完整资料的方式绕过。
- 如果公开页面出现缺图，依据资源清单补充缺失文件并重新发布。
- 如果发现敏感或不应公开的内容，在站点验收前从提交中移除；若已经推送，则立即从当前分支移除并评估是否需要清理 Git 历史。
