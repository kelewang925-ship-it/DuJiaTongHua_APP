# 《独家童话》项目展示 HTML 设计说明

日期：2026-09-04  
状态：待用户确认后进入实现计划

## 1. 目标

在 `项目资料/` 根目录新增一个可离线打开的单文件 HTML 页面，用于集中展示《独家童话》的品牌定位、产品结构、当前八个设计模块、代表设计稿、页面功能、用户流程、设计体系和项目状态。

页面以对外可展示的品牌档案为主，同时保留足够的内部状态信息，帮助设计、开发和项目维护人员区分“已有设计稿”“已完成视觉审批”“已有代码实现”和“规划中能力”。

拟定输出文件：

`项目资料/独家童话-项目展示.html`

## 2. 受众与使用场景

主要受众：

- 需要快速了解项目定位、模块与视觉方向的合作人员。
- 需要检查模块、页面和设计稿覆盖情况的项目维护者。
- 需要浏览当前设计成果的产品、设计和开发人员。

主要使用场景：

- 双击 HTML 文件，在本地浏览器中离线查看。
- 通过页面导航快速跳转到品牌、产品、模块、设计稿、功能和状态区域。
- 按模块查看代表设计稿，并打开大图预览。
- 从展示页跳转到项目资料中的 Markdown、流程图和设计稿目录。

## 3. 内容来源与事实基准

页面以以下资料为当前事实来源：

1. `项目资料/资料索引.md`
2. `项目资料/01-项目总览/项目介绍.md`
3. `项目资料/02-产品与功能/产品结构.md`
4. `项目资料/02-产品与功能/所有页面功能清单.md`
5. `项目资料/新模块分布/设计整理与后续执行计划.md`
6. `项目资料/新模块分布/` 各模块根层正式 PNG
7. `项目资料/09-流程图/用户使用流程.png`
8. `项目资料/05-图片资产与生成/独家童话-App图标-当前选定版.png`

展示页必须遵守以下数据口径：

- 当前设计稿以 `项目资料/新模块分布/` 下的八个模块为唯一基准。
- 当前共有 114 张正式页面与状态稿，约 89 个逻辑页面。
- `历史未通过/`、旧 67/69 页计划和旧九模块设计稿不得混入当前设计展示。
- 模块 03 的三张探索提案不作为正式页面展示。
- 设计稿完成、视觉审批通过、代码实现完成和真实设备验证通过是不同状态。

## 4. 信息架构

### 4.1 顶部导航

采用单行吸顶导航，包含：

- 项目
- 产品
- 模块
- 流程
- 设计稿
- 设计体系
- 当前状态

移动端折叠为可水平滚动的章节导航，不使用复杂抽屉。

### 4.2 品牌封面

展示：

- 当前选定 Logo
- 项目名称《独家童话》
- 核心表达：“把恋爱过程，慢慢写成一本只属于两个人的童话绘本。”
- 一段不超过 50 字的产品介绍
- 四个关键数据：4 个核心 Tab、8 个设计模块、114 张正式稿、约 89 个逻辑页面

封面只建立品牌印象，不放功能长列表和设备模型。

### 4.3 项目与核心价值

用四个连续叙事节点展示：

1. 记录日常
2. 共同创造
3. 重新发现回忆
4. 收藏两个人的故事

内容强调情侣共同参与，而非普通个人日记或公开社交产品。

### 4.4 产品结构

同时呈现两个层级：

- 四个主 Tab：首页、情侣空间、童话工坊、我的。
- 八个当前设计模块：账号登录、账号关联、童话首页、重要时刻、童话工坊、我的与设置、情侣宠物、共同回忆册。

使用“四个入口承载八个业务模块”的关系布局，避免误导为八个底部导航。

### 4.5 用户流程

引用现有 `用户使用流程.png`，并配合简短文字说明：

引导与登录 → 情侣关系建立 → 首次共同任务 → 日常记录与共同创作 → 回忆再发现与收藏。

流程图可点击放大。

### 4.7 代表设计稿画廊

第一版展示每个模块 2–3 张代表稿，总量控制在约 20 张。

画廊支持：

- 按模块筛选
- 点击打开大图灯箱
- 上一张/下一张
- `Esc` 关闭
- 图片懒加载
- 图片加载失败时显示文件名和资料路径

第一版不把全部 114 张图片直接铺满页面。完整设计稿浏览器作为后续增强，不阻塞首版。

### 4.8 页面功能

功能内容按模块组织，每个模块先展示核心任务，再提供可展开的页面明细。

页面明细字段：

- 页面名称
- 主要任务
- 设计状态
- 实现状态
- 备注

不得把“存在设计稿”表述为“功能已开发”。对于情侣宠物、共同回忆册等规划能力，必须显示真实状态。

### 4.9 设计体系

展示：

- 当前选定 Logo
- 品牌核心概念
- 月白、桃夭、藕丝秋半、枯玫瑰、可可棕和琥珀金
- 奶油纸张、绘本、回忆收藏和双人宇宙等视觉关键词
- 设计中应避免的高饱和粉色、低幼卡通、强科技 AI 风和公开社交感

该区域是简洁样式板，不复制完整 Design System 文档。

### 4.10 当前状态

明确展示：

- 八个模块最近一轮设计稿已经整理完成。
- 114 张正式页面与状态稿尚未完成最终视觉审批。
- 页面复杂度和装饰密度仍待专项评审。
- 设计稿与现有代码路由不是一一对应关系。
- 规划功能不得标记为已经开发完成。

统一状态词：已设计、待视觉审批、已开发、开发中、规划中、历史归档。

### 4.11 资料入口

页面底部提供指向项目资料的相对链接，包括项目介绍、产品结构、页面功能清单、八模块目录、流程图、设计系统和图片资产记录。

## 5. 视觉方向

页面类型：编辑型品牌档案，不是企业官网、后台仪表盘或纯图片瀑布流。

设计参数：

- 固定浅色主题
- 设计变化度：6/10
- 动效强度：3/10
- 信息密度：5/10

颜色：

- 页面背景：月白与暖象牙
- 主要文字：可可棕
- 品牌强调：桃夭粉
- 次级强调：枯玫瑰
- 少量高光：琥珀金

版式：

- 宽屏使用编辑型非对称排版和大幅设计稿。
- 移动端改为单列，保持正文与图片可读性。
- 使用统一圆角体系、纸张分层、克制阴影和少量材质感。
- 不使用满屏粉色、连续等宽卡片、复杂视差或大量漂浮装饰。

字体采用离线安全的系统字体栈，不从网络加载字体。

## 6. 技术架构

页面为一个独立 HTML 文件：

- HTML、CSS、JavaScript 全部内嵌。
- 所有项目图片使用相对于 `项目资料/` 的路径。
- 不依赖 npm、React、CDN、在线字体或远程图片。
- 代表设计稿、模块数据和资料链接以内嵌 JavaScript 数据维护。
- 浏览器不能自动扫描本地目录，因此图片清单必须显式写入页面数据。
- 图片使用原文件，不复制或重新编码现有设计稿。

JavaScript 只负责：

- 章节导航状态
- 模块筛选
- 功能明细展开
- 大图灯箱
- 键盘操作

页面在 JavaScript 不可用时仍应能阅读主要文本和代表图片。

## 7. 响应式与无障碍

- 桌面、平板和手机均可浏览。
- 图片包含可理解的 `alt` 文本。
- 所有按钮可键盘操作并有清晰焦点状态。
- 灯箱打开后焦点进入灯箱，关闭后返回触发元素。
- 颜色不作为状态的唯一表达方式。
- 尊重 `prefers-reduced-motion`，关闭非必要动画。
- 页面不得产生明显横向溢出。

## 8. 错误与降级处理

- 图片不存在或路径错误时，显示占位区域、文件名和相对路径。
- 单张图片加载失败不得影响其他内容。
- JavaScript 关闭时，导航锚点、正文和基础图片仍可访问。
- 不读取或执行 Markdown 文件内容，只提供链接，避免浏览器本地权限问题。

## 9. 验收标准

内容验收：

- 当前数据口径与八模块基准一致。
- 历史未通过稿和探索提案未进入正式展示。
- 至少包含 Logo、项目介绍、结构、流程、模块、代表设计稿、功能、设计体系和当前状态。
- 设计状态和实现状态明确分开。

视觉验收：

- 首屏能在一个视口内建立品牌与产品认知。
- 页面不退化为重复卡片墙或超长图片列表。
- 代表设计稿在桌面和手机上清晰可读。
- 全页保持统一浅色主题、配色和圆角体系。

功能验收：

- 本地双击 HTML 可正常打开。
- 所有章节锚点可用。
- 模块筛选和功能展开正常。
- 灯箱支持鼠标和键盘操作。
- 资料相对链接与图片路径有效。
- 浏览器控制台没有未处理异常。

## 10. 首版范围外

- 不在页面内嵌全部 114 张正式稿。
- 不实现自动扫描文件夹或实时同步 Markdown。
- 不部署到公网。
- 不修改 Expo 应用代码、路由或现有设计稿。
- 不为该页面引入构建工具、框架或第三方依赖。
