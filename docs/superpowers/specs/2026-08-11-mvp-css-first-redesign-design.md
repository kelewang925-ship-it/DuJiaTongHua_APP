# 《独家童话》MVP CSS 主导重设计方案

## 状态

- 方案状态：已确认
- 设计范围：第一阶段 7 个 MVP 页面
- Figma 状态：暂不修改，等待后续单独授权
- 实现状态：尚未开始

## 1. 目标

将第一阶段页面从“图片驱动的页面视觉”调整为“CSS/RN 原生布局驱动的页面视觉”。

页面的背景、卡片、按钮、输入框、标签、时间线、导航和主要信息层级由 React Native 组件与样式完成；图片只用于用户内容、AI 作品、少量插画、透明贴纸和图标点缀。

目标是让页面在手机、平板和 Web 宽屏下保持稳定，不因大面积图片被拉伸、压缩或固定尺寸锁死，同时保留温暖、克制、具有绘本感的品牌气质。

## 2. 已确认的设计路线

采用“CSS 主体 + 轻量插画点缀”。

不采用纯图片页面，也不强制移除所有已有图片。已有图片将按语义重新分配使用场景：

- 内容图：用户照片、AI 漫画、作品封面，保持独立比例展示。
- 小插画：用于登录、空状态、童话工坊入口等局部场景。
- 装饰贴纸：心形、花朵、星星、胶带、魔法棒等，控制尺寸和数量。
- 图标：优先使用现有 Ionicons 或 FairySvgIcon，不用大 PNG 模拟按钮或页面结构。

禁止用未经处理的大图承担整页背景、按钮、输入框、Tab、卡片结构或固定高度布局。

## 3. 基础视觉系统

### 3.1 背景与表面

默认使用 React Native 样式颜色，不把纸张纹理作为基础依赖。

| 用途 | 方向 |
| --- | --- |
| 主背景 | 暖米白 `#F8F6F2` |
| 次级背景 | 奶油纸色 `#FDFBF7` |
| 分区背景 | 浅玫瑰色 `#F5EAE6` |
| AI/特殊功能 | 浅金色 `#F7E8D5` |
| 主要文字 | 深棕色 |
| 强调文字 | 玫瑰色或金色 |

纸张纹理只作为后续可选的低透明度增强层；透明处理、裁切和压缩不应阻塞本方案落地。

### 3.2 卡片

- 普通卡片使用 CSS/RN 背景、边框和阴影。
- 强调卡片使用浅粉或浅金表面。
- 圆角统一使用 16、24、32 三档。
- 内边距统一使用 16、20、24 三档。
- 阴影低透明度、低扩散，避免厚重悬浮感。
- 卡片高度由内容撑开；只有媒体预览使用固定比例容器。

### 3.3 布局与响应式

- 4px 作为基础间距单位。
- 页面左右边距默认 16px，宽屏可扩展至 24px。
- 模块间距 20–24px。
- 主要按钮高度 48–52px。
- 移动端单列优先，平板/Web 宽屏可采用双栏或主内容加辅助信息布局。
- 内容区域需要设置合理的最大宽度，避免 Web 端横向拉伸。
- 延续现有 `compact`/`wide` 适配思路，但后续统一断点和命名。

### 3.4 文字

- 页面只保留一个主要标题层级。
- 标题可以有轻微绘本气质，但正文、按钮和表单必须清晰易读。
- 重要数字使用深棕或玫瑰强调色。
- 避免把长段文字压在图片上。

## 4. 组件策略

优先复用现有组件：

```text
FairyPage
├─ FairyHeader
├─ FairyCard
├─ FairyButton
├─ FairyInput
├─ FairyTag
├─ FairyImage
├─ FairySticker
├─ FairyTimeline / MemoryCard
└─ FairyTabBar
```

只有现有组件无法表达新结构时，才考虑增加通用组件，例如 `FairySection`、`FairyMediaFrame`、`FairyStatCard`、`FairyActionGrid` 和 `FairyChapterCard`。新增组件必须有明确职责和跨页面复用场景。

## 5. MVP 页面结构

### 5.1 登录页

定位为打开一本童话的入口。采用暖米白背景、品牌标题、情绪化欢迎文案、CSS 登录表单卡片、主按钮和小型透明插画。插画不承担表单背景。

### 5.2 首页

定位为“今天的恋爱绘本”。顶部展示日期与通知，核心区域为恋爱天数/今日情绪卡，其后是“把今天写进童话”主入口、日记/照片/AI 作品快捷入口和最近故事流。主视觉焦点是今日状态卡，不再依赖大幅 Hero 图。

### 5.3 写日记页

定位为低压力、沉浸式记录。包含顶部返回与保存状态、日期/情绪/标签、CSS 编辑纸张区域、照片缩略图、AI 生成入口和底部保存操作。照片作为内容插入，不作为编辑器背景。

### 5.4 情侣空间

定位为两个人共同成长的时间轴。包含情侣信息头部、关系状态/恋爱天数、两人统计卡、共同时间线、纪念日章节入口和共同记录列表。时间线使用 CSS 连接线、节点与章节卡，贴纸只做节点或章节标记。

### 5.5 童话工坊

定位为把回忆变成作品的创作空间。包含工坊标题、漫画创作入口、视频/回忆放映入口、最近创作历史以及空状态/生成中状态。使用创作卡片和魔法状态表达 AI，不采用科技面板风格。

### 5.6 我的

定位为私人收藏册。包含个人资料卡、会员/身份状态、记录统计、纪念日、数据/备份/收藏功能列表以及设置与退出。强调秩序和可访问性，不使用大面积插画。

### 5.7 纪念日

定位为两个人的重要章节。包含页面标题、章节数量、最近纪念日倒计时卡、纪念日章节列表和新建按钮。倒计时卡由 CSS 数字、日期和小装饰组成，封面图为可选内容。

## 6. 实施顺序

### 阶段一：公共骨架

先统一页面容器、标题区、卡片、按钮、标签、底部 Tab、响应式容器、CSS/RN 背景和媒体比例规则。

### 阶段二：视觉验证样板

优先设计首页和童话工坊。首页验证无大 Hero 图时的品牌识别度；童话工坊验证 AI 页面在非科技风格下的功能表达。

### 阶段三：扩展核心页面

按以下顺序扩展：情侣空间、我的、纪念日、写日记、登录。

## 7. 验收标准

每个 MVP 页面必须满足：

- 移除所有非必要图片后，页面结构仍然完整。
- 不同宽度下没有图片拉伸、内容溢出或固定高度破坏布局。
- 主要结构由 RN 原生布局和现有通用组件完成。
- 图片可以独立替换、降级或暂时移除。
- 页面有明确的唯一主要视觉焦点。
- 标题、正文、辅助信息和操作按钮层级清晰。
- 空状态、加载状态和错误状态沿用同一视觉系统。
- 至少验证窄屏手机、普通手机和平板/Web 宽屏三类尺寸。

## 8. 当前明确不做的事项

- 不修改 Figma 文件。
- 不开始页面代码重构。
- 不批量处理现有图片透明背景、裁切或压缩。
- 不因为本方案顺手整理无关 Git 工作区内容。
- 不在设计阶段新增大量整页插画或大幅背景资源。
